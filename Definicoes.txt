Curso Docker

Oq é:
	Reduz complexidade de setup das aplicações
	Servidores para rodar na nossa aplicação
	Criar ambientes independentes que funcionam em diveroso SO´s
	Projetos performáticos

Códigos:
    docker version -> Versão

    Ajuda:
        docker run --help
    
    Hub:
        docker login -> Logar antes
        docker push nomeDoSeuUser/imagem -> Mandar para o docker hub

    Rodar:
        docker run ubuntu -> Baixando ubuntu
        docker run -it ubuntu -> Rodar o ubuntu iterando com o ubuntu
        docker run -d nginx -> Roda o nginx sem aparecer varios aviso de dowload, etc. Deixando o terminal livre
        docker run -it --rm ubuntu -> Rodar o ubuntu gerando um container e quando acabar apaga para não ficar aramazenado
        docker run -d -p 80:80 nginx -> Rodar em uma porta (O primeiro 80 é a porta do google por exemplo e a segunda do servidor por exemplo)
        docker start ID -> Rodar um container que foi stop sem rodar interativo
        docker start -i ID -> Rodar um container que foi stop rodando interativo, ou seja mostrando os logs
        docker run -d -p 80:80 --name nginx_app nginx -> Definir o nome do container
        docker pull python -> Baixar e deixar disponivel no ambiente
        docker cp nome:/app/arq ./pasta/ -> Copiar arquivos para uma pasta
    
    Containers:
        docker top name_container -> Ver mais infos sobre um container que está rodando
        docker inspect nome_container -> Ver informações como id, data criação, imagem, etc em JSON
        docker stats -> Ver como anda o processamento, memoria que um container esta gastando
    
    Autenticação:
        docker login -> Logar passando username e password
        docker logout -> Encerrar secção de login

    Enviar imagem para Docker hub:
        docker push nomeHub/nomeimagemHub -> Mandar imagem para o hub
        docker build -t nomeHub/nomeImagem:tag -> Buildar nova versão mudando tag para hub

    Renomear:
        docker tag idImagem novo_nome:nova_tag

    Listagem:
        Docker os -> Ver imgs ativa
        docker container prune -> limpa os containers
        docker ps -a -> Lista todos os containers já executados e executando
        docker container ls -> Lista os container
        docker images -> Ver imagens

    Excluir/Parar:
        docker stop NAMES/IDS -> Para container
        docker rm ID -> Para deletar container
        docker rm NAMES/ID -f -> Para um container e deleta
        docker rmi <imagem> -> Apagar imagem
        docker rmi <imagem> -f -> Força a apagar imagem
        docker system prune -> Remove as imagens, containers e networks não utilizados

    Logs:
        docker logs ID/NAME -> Ver logs do container

    Criar Imagem:
        FROM -> Imagem base
        RUN -> Baixar libs/comandos necessarios
        WORKDIR -> Diretorio da aplicação
        EXPOSE -> Porta
        COPY -> Quais arquivos serão copiados e para onde vai(requirements.txt, workdir)
        CMD ["linguagem/framework", "arq.x"]
        docker build . -> No terminal para rodar o Dockerfile (Caso faça alteração é necessario buildar novamente)
        docker build -t meu_node_builder . -> Colocar name no build
        docker build -t meu_node_builder:nova_tag . -> Colocar tag e nome no build
    
    Volumes:
        Anonimo: docker run -d -p 80:80 --name name_cont --rm -v /data image
        Nomeado: docker run -d -p 80:80 --name name_cont -v nomeVolume:/var/www/html/messages --rm image
        bind mount: docker run -d -p 80:80 --name name_cont -v C:\Caminhodasuapasta:/var/www/html/messages --rm image
        Listar: docker volume ls
        Criar volume manualmente: docker volume create nome
        Inscepcionar o volume: docker volume inspect nome
        Remover um volume: docker volume rm nome
        Remover volumes não utilizados em massa: docker volume prune
        Volume somente leitura: docker run -d -p 80:80 --name name_cont -v nomeVolume:/var/www/html:ro --rm image
    
    Networks:
        Listagem: docker network ls
        Criar: docker network create <nome> (tipo bridge) - docker network create -d macvlan <nome>
        Remover: docker network rm <nome>
        Remover networks que não são utilizados: docker network prune
        Conectando e rodando: docker run -d -p 5000:5000 --name <nomeContainer> --rm --network <nomeNetwork> <nomeImagem> (As imagens conectadas tem que ter esse --network)
        Conectar manualmente um container a uma rede: docker network connect <rede/nomeNetwork> <container>
        Desconectar manualmente um container a uma rede: docker network disconnect <rede/nomeNetwork> <container>
        Inspecionar rede: docker network inspect <nomeNetwork/rede>

    Docker compose:
        Criar arquivo docker-compose.yaml
        Rodar: docker compose up
        Rodar em detached: docker compose up -d
        Parar em background: docker compose down
        Listar: docker-compose ps
    
    Docker swarm:
        Ativar docker swarm: docker swarm init
        Listar nós: docker node ls(se estiver dentro do nó manager) || docker exec -it <manager> docker node ls
        Parar e Remover nos: docker stop <nome> -> docker node rm <nome> || docker node -f rm <nome>
        Remover para não aparecer down: docker exec -it <manager> docker node rm <no>
        Criar nó: docker run -d --privileged --name node1 --hostname node1 docker:dind
        Iniciar no manager: docker exec -it node1 docker swarm init
        Juntar ao cluster: docker exec -it node2 docker swarm join --token <COLE_O_SEU_TOKEN_AQUI> <IP_DO_MANAGER>:2377
        Criar serviço: docker service create --name <nome> <imagem>
        Listar serviços: docker service ls
        Liberar porta: docker service update --publish-add 8080:80 <nome>
        Remover seviço: docker service rm <nome>
        Replicar serviço: docker service create --name <nome> --replicas <numero> <imagem>
        Recuperar token: docker swarm join-token manager
        Rebaixar de poder: docker node demote <nome>
        Ver informações: docker info
        Deixar nos: docker swarm leave
        Inscepcionando serviço: docker service inspect <id>
        Inscepcionar serviço: docker service ps <id>
        Compose: docker stack deploy -c <arquivo_yaml> <nome>
        Escalar serviços: docker service scale <nome>=<replicas>
        Não receber mais ordens do manager: docker node update --availability drain <id>
        Atualizar imagem: docker service update --image <imagem> <servico>
        Criar rede: docker network create --driver overlay swarm 
        Concetando serviço a uma rede: docker service update --network <rede> <nome> 
    
    Kubernets:
        kubectl version -> Ver versão
        minikube version -> Ver versão
        minikube start --driver=docker -> Startar o minikube (sempre que o computador for reiniciado, devemos iniciar o minikube)
        minikube status -> Ver status
        minikube stop -> Parar minikube
        minikube dashboard -> Ver detalhes do projeto como: serviços, pods e etc
        minikube dashboard --url -> Obter apenas a url
        docker push imagem -> Mandar 
        kubectl create deployment <NOME> --image<IMAGEM> -> Criar deployment
        kubectl get deployments -> Verificar deployment
        kubectl describe deployments -> Mais detalhes do deployment
        kubectl get pods -> Verificar os pods
        kubectl describe pods -> Mais detalhes
        kubectl config view -> Verificar como o kubernetes está configurado
        kubectl expose deployment <NOME> --type=<TIPO> --port=<PORT> -> Criar serviço e expor nossos Pods, primeiro nome do deployment, tipo LoadBalancer é o mais comum
        minikube service <NOME> -> Acessar serviço, ip aparece no terminal e uma aba é aberta
        kubectl get services -> Ver serviços
        kubectl describe services/<NOME> -> Ver serviço especifico
        kubectl scale deployment/<NOME> --replicas=<NUMERO> -> Criar replica de pods
        kubectl get rs -> Checar replicas
        kubectl scale deployment/<NOME> --replicas=<NUMERO_MENOR> -> scale down, reduzindo o número de Pods
        kubectl set image deployment/<NOME> <NOME_CONTAINER>=<NOME_IMAGEM> = Atualizar imagem
        kubectl rollout status deployment/<NOME> -> Verificar uma alteração
        kubectl rollout undo deployment/<NOME> -> Desfazer uma alteração
        kubectl delete service <NOME> -> Deletar service
        kubectl delete deployment <NOME> -> Deletar deployment
        kubectl apply -f <NOME_ARQ> - Rodar no modo declarativo o deployment ou o service
        kubectl delete -f arquivo -> Parar o deployment ou service

Conceitos: 
    Imagem -> É o projeto que será executavel pelo container, todas instruções estarão declaradas nela
    Container -> Docker rodando alguma imagem, consequentemente executando algum código proposto por ela
    Fluxo -> Programamos uma imagem e a executamos por meio de um container
    Container x VM -> Container serve para um determinado fim, euqnato vm tem seu so proprio e pode executar diversas funções ao mesmo tempo
    Layers(camadas) -> Cada instrução no dockerfile representa uma layer, quando algo atualizado apenas as layers depois da linha atualizada são refeitas, tornando o build mais rápido
    Volumes: Anônimos, Nomeados ou Bind mounts(salva na máquina). Persiste valores mesmo após a remoção de containers
    Network: Realizar comunicações externas(APIs), host e entre containers
    Drivers: Definem como o network se comporta, com seus devidos tipos que são eles:
        Bridge: Utilizado quando containers precisam se comunicar
        host: Conexão entre um container e a máquina
        macvlan: Conexão entre um container por um MAC address
        none: Remove todas as conexões de rede de um container
        plugins: Permite extensão de terceiros para criar outras redes
    YAML(yml ou yaml): Usado geralmente para arquivos de configurações, inclusivo no Docker, para configuirar o Docker Compose
    Docker Compose: Ferramenta para roda multiplos containers, com um arquivo de configuração(yaml), rodando multiplos builds e runs com um comando
    Orquestração: Gerenciar e escalar os containers, rege sobre outros serviços, serviços: Docker Swarm, Kubernetes e Apache Mesos
    Docker Swarm: Ferramente de orquestração, escalar horizontal(compartilhando recursos), o famoso cluster. Conceitos:
        Nodes: É uma instância (máquina) que participa do swarm
        Manager node: Node que gerencia os nodes
        Worker Node: Nodes que trabalham em função do manager
        Service: Conjunto de Tasks que o Manager Node manda o Work Node executar
        Task: comando que são executados nos nodes
    Kubernetes:
        Ferramenta de orquestração de container, prmitindo a multipla criação de containers em diferentes máquinas (nodes), criado pelo google permite que sejam executadas sempre da mesma forma

        Control pane: Gerencia o controle dos processos dos Nodes
        Nodes: Máquinas que são gerenciadas pelo control Plane
        Deployment: Execução de uma imagem/projeto em um Pod
        Pod: Um ou mais containers que estão em um Node
        Services: Serviços que expõe os Pods ao mundo externo
        kubectl: Cliente de linha de comando para o Kubernetes
        Chaves mais utilizafas do modo declarativo:
            apiVersion: versão utilizada da Ferramenta
            kind: tipo do arquivo(Deployment, service)
            metadata: descrever algum objeto
            replicas: número de replicas de Nodes/Pods
            containers: especificação de containers
